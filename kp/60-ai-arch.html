60 · AI 与大模型架构

1一句话核心

训练是建厂、推理是开工，服务靠缓存分流与算力调度。

2先想后学：真实工程场景

🏗️ 场景公司决定上「大模型智能客服」。立项会上老板连问三枪：① 直接调个大模型 API 不就完了？② 它把退款政策编得有鼻子有眼（其实是胡说），客户拿着截图来投诉，怎么办？③ 高峰期五千人同时问，显卡只有十张，怎么办？你是架构师——直接回答这三枪，还是先承认「大模型≠客服系统」？
💡 点开看思路与答案

三枪各有对策，合起来才是「智能客服架构」：① 直接调 API 只解决了「会说话」，没解决「说得对、说得稳、说得便宜」——需要模型服务化 + 分流（80% 高频重复问题用 FAQ（常见问题集）缓存与小模型承接）。② 胡说叫幻觉，生成模型的机制性副作用：用 RAG 检索增强——先去知识库把相关政策原文查出来拼进提示词，让模型「照着资料答」，查不到就拒答转人工。③ 算力不够靠架构而非堆卡：意图识别分流 + 相似问题缓存 + GPU 算力池统一调度 + 批处理推理。记住：模型是参谋，架构才是让参谋稳定上岗的那套班子。

3知识卡片

是什么：机器学习三范式

范式怎么学典型例子
监督学习拿「题目+标准答案」（标注数据）学，最常见垃圾邮件识别（分类）、房价预测（回归）
无监督学习没有标签，自己找结构与规律用户分群聚类、降维、异常检测
强化学习试错+奖励反馈，在环境里摸出策略棋类 AI 自我对弈、机器人控制、推荐调优

一句话记：监督是师傅带徒弟对答案，无监督是自己分堆找规律，强化是下场练球靠输赢长记性。

AI 工程流程：数据到监控的闭环

数据采集 → 清洗标注 → 特征工程 → 模型训练 → 评估验证 → 部署上线 → 监控迭代。两条铁律：① 数据质量决定模型上限——垃圾进垃圾出；② 上线不是终点——真实数据的分布会漂移（用户变了、市场变了），模型会退化，必须监控指标并触发再训练，形成闭环。

训练 vs 推理：建厂与开工

维度训练（建厂）推理（开工）
任务性质一次性/周期性大作业，离线批处理长期在线服务，7×24 响应用户
资源形态GPU 集群整块占用，跑完释放常驻服务，显存长期被模型占着
核心指标精度/收敛速度/训练吞吐时延、吞吐、成本（单次调用价格）
架构手段分布式训练（数据并行/模型并行）、GPU 算力池统一调度模型服务化、请求批处理、KV/相似问题缓存、分流降级、弹性伸缩

易被忽略的账：训练是一次性投入，推理成本长期占大头（每天千万次调用 × 电费与卡折旧），所以推理架构是性价比的主战场。

大模型四要点

① Transformer 与注意力机制（一句话版）：模型读每个词时会「环顾全文」，给相关的词分配不同权重（自注意力），因此能捕捉长距离上下文。② 预训练+微调：先在海量无标注文本上预训练出通用语言能力，再用少量领域数据微调（或提示工程、指令微调）上岗——「通才先读书，再上岗位培训班」。③ RAG 检索增强生成：回答前先去知识库检索相关资料拼入上下文，让模型「照资料答」——治幻觉、知识随时可更新、不必重训模型；查不到就拒答。④ Agent 智能体：给参谋配手脚——规划任务、调用外部工具（查库、下单、发邮件）、带记忆地多步执行。

端云协同部署（伏笔 → 61 页）

云端大模型能力强但时延与带宽受限；端侧/边缘侧部署小模型（蒸馏、量化后）可离线运行、保护隐私。典型分工：端侧小模型做实时简单任务，云端大模型做复杂任务，端云协同才是完整答案——与 61 页云边端协同一脉相承。

「智能客服系统」架构素材（论文可整段复用）

接入层（APP/网页/电话多渠道统一接入）→ 网关（鉴权、限流、防刷）→ 意图识别（规则+小模型，把「查订单」类高频简单意图直接走 FAQ/缓存）→ 大模型推理服务（GPU 池、请求批处理、超时降级）→ RAG 知识库（政策文档向量化入库，先检索后生成）→ 合规层（敏感词过滤、答案溯源展示）→ 人工兜底（低置信度/高风险会话转人工）→ 数据回流（会话与人工纠正结果回流入库，用于再训练与评估）。

🔤 专业英语Fine-tuning（微调）· RAG（Retrieval-Augmented Generation，检索增强生成）· Inference（推理）
⚠️ 易错点① 幻觉不是「修个 bug 就没了」：它源于生成机制（模型在「续写最像的话」，不是在「查证」），只能靠 RAG、拒答、答案溯源等架构手段压制；② 「大模型=数据库」是错的——它会生成不存在的事实，事实性必须外挂知识库；③ 训练贵≠推理便宜，推理是长期成本大头；④ 评估不是上线前做一次：数据漂移会让模型「悄悄变笨」；⑤ 分流的第一层是意图识别，不是所有请求都值得动用大模型——高频简单问题先被 FAQ 拦下才是省钱关键；⑥ 端云协同不是「端上放个大模型」，端侧跑的是蒸馏/量化后的小模型。

4生活类比与口诀

未来新城里，AI=规划参谋部。三范式是参谋的三种成长方式：监督学习=师傅带着对答案（每道题都有标准答案）；无监督=发一堆资料让他自己归类找规律；强化=下场练球，赢了表扬输了复盘。训练=参谋进修：脱产几个月、集中营式苦读（GPU 集群整块占用）；推理=上岗值班：每天接待无数来访，回答要快、要稳、便宜（在线服务，时延吞吐成本）。RAG=先查档案馆再回答：参谋再博学也会记错政策，回答前先去中央档案馆把文件原文翻出来摆在桌上，照着答——文件更新了，参谋不用重新上学。Agent=给参谋配手脚：不但出主意，还能亲自查系统、下工单、订会议室。端云协同：社区服务站（端侧小模型）处理小病小痛，疑难杂症转总部参谋部（云端大模型）。

  • 项目情景模板：智能客服 / 企业知识库问答 / 辅助写作助手。论证主线：背景 → 大模型直接上线的三宗罪（幻觉、成本、合规）→ 分层架构设计 → 量化收益（时延、成本、准确率）→ 遗留问题（数据飞轮建设与持续评估）。
  • 论点句式：「建立『采集-标注-训练-评估-监控』闭环：上线后持续监控数据漂移与业务指标，指标劣化自动触发再训练与灰度回归，避免模型随业务演化而退化。」
  • 备考提示：大模型类论文的采分点在「工程化」——服务化、分流、缓存、算力调度、监控评估；写成模型科普文拿不到分。

易混概念对比

训练（Training）推理（Inference）
性质离线大作业：用数据「调」出模型参数在线服务：用固定参数响应用户请求
核心指标精度、收敛速度、训练吞吐时延、吞吐、单次调用成本
易错点以为训完就一劳永逸——数据漂移会让模型退化以为推理是「小钱」——每天千万次调用，长期成本往往超过训练
一句话区分训练是建厂（一次投入大），推理是开工（天天运转、成本细水长流）——工厂建得再好，开工省钱才是经营日常。

10小结

  • ① 三范式各记一个例子：监督=垃圾邮件识别、无监督=用户分群、强化=自我对弈；工程主线是「数据→训练→评估→部署→监控」的闭环，数据质量决定上限。
  • ② 训练是建厂（离线、整占 GPU、看精度），推理是开工（在线、常驻、看时延吞吐成本）；推理靠服务化、批处理、缓存、分流、算力池省钱提速。
  • ③ 大模型四要点：注意力机制一句话（读每个词时环顾全文分配权重）、预训练+微调、RAG 先查档案馆再回答（治幻觉免重训）、Agent 给参谋配手脚；端云协同=端侧小模型+云端大模型。
