12 · 分页分段与虚拟内存

1一句话核心

页表把假地址翻译成真地址，缺页才进城调页，置换算法定缺页率。

2先想后学：真实工程场景

🏗️ 场景一台 8GB 内存的开发机，同时跑着总申请内存 20GB 的十几个容器和 IDE，居然都能正常运行，只是偶尔卡顿。free 命令显示物理内存早满了，但磁盘上的 swap 分区很忙。问题：8GB 怎么装下 20GB？「偶尔卡顿」又卡在哪？
💡 点开看思路与答案

每个进程拿到的是虚拟地址空间——它以为自己独占整座城市的地址编号；真正装进物理内存的只是当前活跃的那部分页，其余放在磁盘（swap）里，用到时经缺页中断调入。这是「部分装入+按需调页」的虚拟内存机制。偶尔卡顿正是缺页：要访问的页不在内存，得从磁盘读入——磁盘比内存慢十万倍量级，一次缺页就是一次明显停顿。程序整体能跑，靠的是 局部性原理：任意时刻只活跃着页集合的一小角。

3知识卡片

是什么

虚拟内存（Virtual Memory）= 程序只部分装入内存即可运行 + 运行中按需调页 + 内存不够时置换。它让每个进程活在统一的「假地址」（逻辑/虚拟地址）里，由页表负责把假地址翻译成真地址（物理块号+页内偏移）。这一层「主存↔磁盘」的调度，与 05 页「Cache↔主存」同构，共同的地基都是局部性原理。

解决什么问题

物理内存装不下所有程序；连续分配又产生大量碎片、程序大小受物理内存硬约束。分页把内存切成等长页框「按页装填」，虚拟内存进一步允许「先装一部分」，程序大小不再受物理内存限制，多道程序度也上去了。

核心机制：三种存储管理方式对比

维度分页分段段页式
划分单位等大小的页（物理切，对用户透明）不等长的段（按逻辑意义切）先分段，段内再分页
地址结构一维：页号 + 页内偏移二维：段号 + 段内偏移二维：段号 + 段内页号 + 页内偏移
越界检查偏移必小于页长，不用查必须查「偏移 < 段长」查段长，再查页表
典型碎片页内碎片（内部碎片）段间外部碎片页内碎片
目的提高内存利用率（系统视角）模块化、共享与保护（用户视角）两者兼得

核心机制：地址翻译与缺页

页式翻译公式：物理地址 = 块号 × 页大小 + 页内偏移（页内偏移原样照抄）。页号 = 逻辑地址 ÷ 页大小取整。查页表前先查快表 TLB（Translation Lookaside Buffer，页表项的高速缓存）：命中省一次访存。要访问的页不在内存时硬件发缺页中断——它与一般中断有三点不同：在指令执行期间产生并立即处理、一条指令可能引发多次缺页、属内中断。操作系统调页入内存，必要时按置换算法淘汰一页。

核心机制：置换算法

算法淘汰谁要点
OPT 最佳以后最长时间不再用的页需要预知未来，无法实现，作性能基准
FIFO 先进先出最早进入内存的页实现简单；有 Belady 异常（物理块加多缺页反而可能变多）
LRU 最近最久未用最长时间没被访问的页看「过去」近似 OPT；开销大（要记访问时间戳）
CLOCK（NRU 近似）引用位为 0 的页（二次机会）给每页一个引用位，循环扫描：1 清 0 跳过，0 淘汰

缺页率 = 缺页次数 ÷ 访问总次数。有效访问时间 EAT ≈ (1−p)×内存访问时间 + p×缺页处理时间（教材口径，忽略快表时）；p 稍大 EAT 就爆炸，因为缺页处理是一次磁盘 I/O。

关键细节：抖动（颠簸，Thrashing）

分配给进程的物理块数少于它的工作集（当前活跃页集合）时，刚换出的页马上又要用，页面在内存和磁盘之间来回搬，CPU 几乎全在等缺页 I/O——利用率骤降。对策：按工作集分配物理块、降低多道程序度、加内存或优化程序局部性。

专业英语小贴士

Virtual Memory（虚拟内存）、Page Fault（缺页/缺页中断）、TLB = Translation Lookaside Buffer（快表/旁路缓冲）。英语题干中「resident set」指驻留集（分到的物理块集合）。

⚠️ 易错点 ① 物理地址 = 块号（查页表得来）× 页大小 + 偏移；偏移原样照抄，别拿页号去乘。
② Belady 异常是 FIFO 独有：物理块从 3 加到 4，缺页可能反而更多；LRU/OPT 没有此病。
③ 段式地址是二维的（段号，段内偏移），两个二维地址相加没有意义——这是段式与页式最经典的判别点。
④ 快表 EAT 要分「命中/未命中」两条路径分别加权，未命中路径里 TLB 时间与内存访问时间是累加的。

4生活类比与口诀

🏛️ 市政厅的地址翻译处：每个商户拿到的门牌号都是「假地址」，从 1 开始随便编（虚拟地址空间）；翻译处案头有一本对照表（页表），把假门牌翻成仓库里的真货位（物理块号+偏移）。案头还压着一张常用速查卡（快表 TLB），翻得飞快。要找的货还没运进城（缺页），就派人从城外档案馆调货（磁盘 I/O）；仓库货架满了，先撤「最久没人动」的货（置换）。如果一批货进城刚上架就被撤下、下一秒又要进城——装卸口就被自家货堵死了（抖动）。

10小结

  • ① 虚拟内存 = 部分装入 + 请求调页 + 置换；页表负责「假地址→真地址」，快表用局部性原理给翻译提速。
  • ② 物理地址 = 块号×页大小+偏移（偏移照抄）；段式地址是二维的且要查段长，段页式兼取两家。
  • ③ 置换看缺页率：LRU 看过去近似 OPT，FIFO 简单但有 Belady 异常；缺页率高到磁盘忙、CPU 闲就是抖动。
