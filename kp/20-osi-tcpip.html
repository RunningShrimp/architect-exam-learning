20 · OSI与TCP/IP分层

1一句话核心

网络分层像邮政体系：写内容、装信封、写地址、运输，各层只管自己那道工序。

2先想后学：真实工程场景

🏗️ 场景凌晨两点，值班工程师小林收到告警：「用户反馈 App 图片加载不出来」。他 ping 服务器通了，telnet 443 端口也通，可图片 URL 返回的是 404。开发说「网络没问题」，网管说「服务器没问题」，僵持两小时。队长只问一句：「这个故障发生在第几层？」——你会怎么答？
💡 点开看思路与答案

先把线索按层放好：ping 通 = 网络层可达；443 能建立连接 = 传输层正常；返回 404 = 应用层（HTTP）的明确响应——网络其实是通的，是「资源不存在」。故障最可能落在应用层（路径改了、存储挂了、网关转发规则错了）。分层模型的价值就在这里：把「网络不通」这种模糊抱怨，切成逐层可验证的子问题，每层有自己的判据，定位到层就能明确谁负责。学完本页，你要能对任何网络问题先问一句：「这是第几层的事？」

3知识卡片

是什么

网络分层，是把「把数据从一台机器送到另一台机器」这件复杂的事，拆成若干道独立工序，每道工序就是一层。国际上形成了两套著名口径：OSI 七层参考模型（ISO 国际标准，先有模型后有协议）和 TCP/IP 四层体系结构（工程事实标准，先有协议后有模型）。每层只对上层提供服务、只调用下层的服务，同层之间靠「协议」（事先约定的对话规则）对话——这就是对等通信。

解决什么问题

不同厂商、不同技术的设备要互联互通。若没有统一分层，每家做一套私有做法，谁也联不上谁；分层之后，层与层之间的接口标准化，某一层的内部技术升级（双绞线换光纤、集线器换交换机）不影响上下层——写信人完全不用关心邮车换了型号。

核心机制：封装与解封装

发送方自上而下逐层「封装」：应用产生数据，传输层加头部变成段，网络层加 IP 头变成分组（包），数据链路层加帧头帧尾变成帧，物理层变成比特流发送。接收方自下而上逐层「解封装」：拆帧头、拆包头、拆段头，最后把原始数据交给应用进程。每一层的头部只有「同一层」的对等实体读得懂——就像信封上的地址只有邮递员看，信纸内容只有收信人看。

速查口令：集线器看不懂地址（物理层）、交换机看懂 MAC（链路层）、路由器看懂 IP（网络层）。这是综合知识题出现频率最高的设备归属结论。

专业英语小贴士（综合知识英语题固定 5 分）
layering / encapsulation分层 / 封装——「each layer adds its own header（每层加自己的头）」
peer communication对等通信——同层实体按协议对话，不对下层细节感知
PDU (Protocol Data Unit)协议数据单元——比特 bit → 帧 frame → 分组 packet → 段 segment
⚠️ 易错点① 设备归属：集线器（物理层）≠ 交换机（数据链路层）≠ 路由器（网络层）；网关在概念上对应高层。② ARP 按主流教材口径归网络层（个别教材归链路层，答题注明口径）。③ TCP/IP 只有四层，没有独立的会话层和表示层，其功能并入应用层——别答成「被取消了」。④ 封装方向：发送端自上而下加头，接收端自下而上拆头，考试常把顺序倒过来当干扰项。

4生活类比与口诀

本域统一比喻：分层 = 邮政体系。你写信（应用层内容），邮局把信装进标准信封（封装），分拣员按城市和门牌分拣（网络层按 IP 寻址），运输公司承运并要求签收（传输层），最后由卡车沿着道路把信送到（物理层与链路层）。

10小结

  • ① 分层 = 把「可靠送到」拆成各管一段的工序：物理传比特、链路发帧、网络找路、传输找进程、应用办业务。
  • ② 发送端逐层封装加头、接收端逐层解封装拆头，同层只读自己的头（对等通信）。
  • ③ 必背归属：集线器=物理层、交换机=数据链路层、路由器=网络层；OSI 七层 vs TCP/IP 四层的对应关系。
