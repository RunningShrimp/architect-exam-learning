22 · IP地址、子网与路由

1一句话核心

子网掩码划出院墙，路由协议是各个路口导航员的信息互通机制。

2先想后学：真实工程场景

🏗️ 场景公司申请到 192.168.10.0/24 一个 C 段。研发部 100 台、产品部 50 台、服务器区 20 台，要求三个部门互相隔离，且未来一年各自可能扩容 20%。行政把 IP 拉了个 Excel 手工分配，两周后地址冲突不断。请你用子网划分给个说法：每个部门给哪一段？掩码各是多少？为什么不能「平均分三份」？
💡 点开看思路与答案

答案在地址里「借位」：192.168.10.0/24 的主机位有 8 位。给研发切 /25（主机位 7 位，可用 2⁷−2=126 ≥ 100✓）、产品切 /26（62 ≥ 50✓）、服务器切 /27（30 ≥ 20✓）。分配时从最大需求开始切：研发 192.168.10.0/25，产品 192.168.10.128/26，服务器 192.168.10.192/27，剩下 192.168.10.224/27 留作扩容。「平均分三份」做不到——前缀必须是连续的 1，块大小只能是 2 的幂（128/64/32…），所以子网划分是「对半再对半」的切法。Excel 手工分配的问题：无结构、无法聚合、冲突后难追溯。

3知识卡片

是什么

IPv4 地址是 32 位的「门牌」：前一段是网络位（哪个小区），后一段是主机位（小区里第几户）。子网掩码则说明「院墙砌在哪一位」：掩码为 1 的位是网络位。路由器（网络层的导航员）依据「目的网络号」查路由表逐跳转发。

解决什么问题

门牌若是一长串无结构的编号，路由表就得记下全世界每一台主机的位置，根本存不下；分层编址（网络位+主机位）让路由器只需记住「到哪个小区怎么走」。子网划分进一步把大网切小：隔离广播、按需分配地址、便于权限与安全管理——这正是 21 页「切院子」思想在网络层的延续。

核心机制：按位与与三件套

网络地址 = IP 按位与（AND）掩码；主机位全 1 得广播地址；两者都不能分给主机。主机位有 h=32−前缀 位，则可用主机数 = 2h−2（减去网络地址与广播地址）。CIDR（无类域间路由）用「/前缀长度」取代 A/B/C 分类，掩码不再受 8/16/24 限制。

⚠️ 易错点① 可用主机数忘减 2：主机位全 0 是网络地址、全 1 是广播地址，不能分配——2⁶=64 但可用只有 62。② /26 的掩码是 255.255.255.192，别与 /25（.128）、/27（.224）记混：256−192=64=块大小。③ 问「子网数」时用的是借位数 n（2ⁿ 个），别拿主机位去算。④ 求「某 IP 所在网络」必须按块大小对齐：192.168.1.100/27 的块是 32，100÷32 落在 96~127 块，网络地址是 .96——不是把末位抹零。

4生活类比与口诀

本域统一比喻：IP = 门牌，路由 = 导航员。门牌前几位是「街区」（网络位），后面是「第几户」（主机位）；子网掩码是「院墙位置说明书」；导航员按街区地图指路（路由表），不同导航员有不同的情报来源。

易混概念对比

RIP（距离向量）OSPF（链路状态）
差异点只信邻居的转述（到各处的距离），周期广播整表，跳数≤15每台路由器掌握全网拓扑（链路状态库），用 Dijkstra 自算最短路径树，可分区
易错点以为「跳数少=一定好」——不看带宽，16 跳即不可达以为 OSPF 也限 15 跳——没有此限制，那是 RIP 的口径
一句话区分RIP 听传闻（邻居说什么信什么），OSPF 看地图（拓扑在手自己算）；选型口径：小网 RIP，大网 OSPF，跨 AS 用 BGP。

10小结

  • ① 网络地址 = IP 按位与掩码；主机位 h=32−前缀，可用主机 = 2ʰ−2（全 0 网络、全 1 广播不可用）。
  • ② 划子网=借位：借 n 位得 2ⁿ 个子网，块大小 = 256−末字节掩码值，从最大需求开始切（VLSM）。
  • ③ 路由三杰：RIP 距离向量跳数≤15、OSPF 链路状态可分区、BGP 域间走策略；路由器按最长前缀匹配转发。
