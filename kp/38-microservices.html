38 · SOA与微服务

1一句话核心

SOA 标准契约走总线，微服务按限界上下文拆店独营。

2先想后学：真实工程场景

🏗️ 场景某保险公司的核心系统是一个单体：投保、核保、理赔、缴费在同一进程里，共用一个 Oracle 库。痛点：改一行理赔代码要回归测试整个系统，双周才能集中发布一次；一个报表查询把数据库 CPU 打满，缴费交易跟着超时。领导决定改造，两个问题摆在桌面：① 按什么边界拆？② 「缴费成功→保单生效→发放积分」跨了三个服务，数据不一致怎么办？
💡 点开看思路与答案

① 拆分边界不按技术层、不按代码目录，而按 DDD 限界上下文/业务能力：投保、核保、理赔、缴费各成一家「专业商铺」，各自独享数据库、独立部署扩容。② 跨服务不再有本地事务，需要选型分布式事务：可靠消息 + 幂等补偿的最终一致性（或 Saga/TCC），用「短暂不一致+对账兜底」换「系统整体可用」——这正是本页案例题的标准答案骨架。

3知识卡片

是什么：SOA——统一便民服务中心

SOA（面向服务的架构）把系统能力封装成服务：服务是粗粒度的、可复用的业务功能单元。三大特征：松耦合（服务不依赖彼此的实现与位置）、标准化契约（接口用标准语言描述）、可复用（一个服务多处调用）。三大角色：服务提供者（发布服务）、服务注册中心（登记与发现）、服务消费者（查找并绑定调用）。Web 服务协议栈：SOAP（消息格式）、WSDL（服务描述）、UDDI（注册发现）。ESB（企业服务总线）是 SOA 的主动脉：统一接入、协议转换、消息路由、服务编排与监控——所有服务都插在总线上，像全市业务汇进统一便民服务中心。

是什么：微服务——专业商铺区

微服务把系统按业务拆成一排小而自治的服务，像专业商铺区：按业务拆店、独立经营、店与店之间「网络订货」（轻量通信）。

  • 拆分原则：按业务能力 / DDD 限界上下文拆（一个服务管一个业务域），一个服务能由一个小团队独立负责（康威定律）；
  • 去中心化数据：每个服务独享数据库，禁止跨服务共库直连；
  • 独立部署：改理赔只发理赔，互不牵连，可按需独立扩容；
  • 去中心化治理：技术栈多样、团队自治，用轻量通信（REST/gRPC/消息）。

治理设施（案例题必点名）：注册中心（服务发现）、配置中心（配置集中下发）、API 网关（统一入口：路由/鉴权/限流）、熔断器（下游故障时快速失败防雪崩）、链路追踪（一次请求跨 N 个服务的调用链可视化）、集中日志与监控。

关键细节：通信与一致性

REST vs gRPC：REST 基于 HTTP+JSON——语义直白、生态广、适合对外开放；gRPC 基于 HTTP/2+Protobuf 二进制——性能高、强类型契约、支持流式，适合内部高频调用。分布式事务：跨服务没有本地事务，可选 2PC/XA（强一致但同步阻塞，微服务少用）、TCC（Try 预留-Confirm 确认-Cancel 取消，适合资金类）、Saga（长事务拆成一串本地事务+每步配补偿操作）、消息最终一致（可靠消息+消费方幂等+重试对账）。选型口诀：强一致少用 2PC，资金关键用 TCC，长流程用 Saga 补偿，一般业务用可靠消息最终一致。

🔤 专业英语service-oriented architecture（面向服务的架构）· enterprise service bus（企业服务总线）· bounded context（限界上下文）· circuit breaker（熔断器）· Saga / compensation（补偿）
⚠️ 易错点① 「微服务就是更细的 SOA」只对一半：粒度、通信、治理、数据四个维度都变了，不只是拆得碎；② 「拆得越细越好」错——粒度失衡会造出分布式单体（服务拆了、数据还强耦合，发布仍要一起发）；③ 独享数据库后跨服务查询要走 API 或数据副本，不是直接连别家的库；④ 熔断防的是「雪崩」（下游故障拖垮上游），不是限流（防自己被打垮）——两者常一起上；⑤ UDDI 管注册发现、WSDL 管描述、SOAP 管消息，三者在协议栈里的分工别对调。

4生活类比与口诀

SOA=统一便民服务中心：全市所有办事窗口标准化（WSDL 契约），门口一个总服务台（ESB）负责指路、翻译方言（协议转换）、排号分流（路由编排）。微服务=专业商铺区：餐饮街、数码街各自成店，一家店装修（部署）不扰邻店；顾客（请求）从商场大门（API 网关）进来，拿商场地图（注册中心）找店；某家店爆满（下游故障），门口闸机（熔断器）直接亮「今日已满」，免得顾客堵死整条街（雪崩）。

易混概念对比

微服务分布式单体
拆分依据限界上下文：业务边界清晰、数据自治按技术层硬拆：服务间共享库、接口互相纠缠

易错点以为「拆了就是微服务」——拆完仍共库强耦合只是「分布式单体」常被误当成微服务化成功，实际运维成本翻倍、收益为零
一句话区分真微服务是各店独立经营，分布式单体是把一个大卖场锯成几块还要一起装修。

10小结

  • ① SOA 三特征：松耦合、标准化契约（SOAP/WSDL/UDDI）、可复用；ESB 负责接入、转换、路由、编排。
  • ② 微服务按 DDD 限界上下文拆店：独库、独立部署、去中心化治理，配齐注册/配置/网关/熔断/链路追踪。
  • ③ 分布式事务选型：资金 TCC、长流程 Saga 补偿、一般业务可靠消息最终一致（幂等+对账）。
