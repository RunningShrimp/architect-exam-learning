55 · 项目管理框架

1一句话核心

十大知识领域十本台账，五大过程组循环推进，组织结构定权力。

2先想后学：真实工程场景

🏗️ 场景某公司中标一个智慧园区项目，总经理拍板：「技术为王，把最强的架构师提为项目经理，直接管开发部、测试部（各部门经理照旧管考勤和绩效）。」项目跑了三个月：架构师项目经理要调人，各部门经理说「先完成我部门的季度指标」；要采购服务器，得走部门预算层层审批。这套组织结构里项目经理权力有多大？换哪种结构能解？
💡 点开看思路与答案

这是典型的弱矩阵结构：项目是「借调出来的临时班子」，权力重心仍在职能经理手里——项目经理更像协调员，遇到资源冲突只能「求人」。要解，就往权力光谱右端移：改成平衡矩阵（项目经理与职能经理权力相当，预算共管）或强矩阵（项目经理专职、全权管预算与考核，职能经理只管技术支撑）。极端情况（常年项目制公司）可以直接上项目型组织，成员全职跟项目走。考点就一句话：职能型→弱矩阵→平衡矩阵→强矩阵→项目型，项目经理权力从小到大。

3知识卡片

是什么

项目管理是把知识、技能、工具与技术应用到项目活动上，以满足项目要求。项目是「为创造独特的产品、服务或成果而进行的临时性工作」；运营是持续、重复的日常工作（如运维值班）。项目有明确的起点和终点，运营没有。指挥一座新城的建设，要同时管十件事，这十件事就是十大知识领域；而每件事都要经历「开工→谋定→大干→盯梢→验收」的循环，这就是五大过程组。

解决什么问题

项目最常见死法不是「技术做不出来」，而是「范围无限加、进度无限拖、成本无限超、相关方永远不满意」。管理框架提供一套分账本的清单：出问题时能定位是哪本台账没管好（范围蔓延？风险没识别？沟通不到位？），而不是笼统地说「管理不行」。

核心机制

五大过程组（按时间推进的「阶段视角」）与十大知识领域（按管理内容的「台账视角」）组成一个 10×5 的过程矩阵——教材里 49 个过程都能放进这张表。考试最爱考「某活动属于哪个过程组 / 哪个知识领域」。

五大过程组指挥部动作代表性过程
启动立项挂牌制定项目章程、识别相关方
规划画图纸定预算范围/进度/成本/风险管理计划等（过程最多）
执行开工干活指导与管理项目工作、建设团队
监控盯进度盯账本监控项目工作、整体变更控制（贯穿全程）
收尾竣工验收移交结束项目或阶段（合同收尾+管理收尾）

关键细节

十大知识领域——记忆锚点：十大领域里整合管理统领其余九大领域（它是唯一横跨全部五大过程组的「总指挥台账」），其余九个按「管什么」分四组：

分组知识领域指挥部台账核心问题
总指挥整合管理总台账把所有局部揉成整体，唯一跨五大过程组的领域（含整体变更控制）
管「四要素」范围 / 进度 / 成本 / 质量工程量簿 / 工期主线 / 资金簿 / 验收单做什么、多快、多少钱、多好（客观四约束）
管「人」资源 / 沟通 / 相关方人力簿 / 公告栏 / 花名册谁来干、怎么说、让谁满意
管「不确定」风险 / 采购天气预警簿 / 采购簿出事怎么办、缺什么去买

组织结构对项目经理权力的影响（高频单选，按教材口径）：

结构项目经理权力全职项目人员比例预算控制人相似比喻
职能型很小或没有几乎没有职能经理借调挂名联络员
弱矩阵小少（0~25%）职能经理为主协调员
平衡矩阵小到中少（15%~60%）两者共管与部门经理分权
强矩阵中到大多（50%~95%）项目经理为主专职指挥
项目型大到几乎全权几乎全部项目经理独立兵团

风险管理流程概览（56~58 页只展开其中数学工具，流程本身在本页记牢）：规划风险管理 → 识别风险（头脑风暴、检查表）→ 定性风险分析（概率×影响矩阵排优先级）→ 定量风险分析（EMV、决策树、蒙特卡洛——见 58 页）→ 规划应对（规避/转移/减轻/接受，对威胁；开拓/分享/提高/接受，对机会）→ 监控风险。顺序不能乱：先识别才谈分析，先分析才谈应对。

⚠️ 易错点①「识别相关方」在启动过程组，不是规划组——章程和相关方登记册是启动的两大产出；②整合管理才是统领，别选范围管理；③矩阵型还分强弱，「弱矩阵=项目经理权力小」，别与平衡矩阵混；④项目与运营的区分抓「临时性+独特性」——运维日常不改架构就是运营；⑤定性在前、定量在后，顺序颠倒即错。

专业英语小贴士

project charter（项目章程）；stakeholder（相关方）；process group（过程组）；integration management（整合管理）；matrix organization（矩阵型组织）。

4生活类比与口诀

沿用全站隐喻：软件项目 = 一座新城的建设工程，项目管理 = 📋 建设指挥部。指挥部里挂十本台账（十大知识领域）：总台账（整合）统着工程量簿（范围）、工期主线（进度）、资金簿（成本）、验收单（质量），人力簿、公告栏（沟通）、花名册（相关方）管人，天气预警簿（风险）、采购簿管不确定。台账是「管什么」（知识领域），「开工→谋定→大干→盯梢→验收」是「什么时候管」（过程组）——台账×阶段，才是完整的管理动作。

类比项概念项成立/失效
指挥部十本台账十大知识领域成立
开工→谋定→大干→盯梢→验收启动→规划→执行→监控→收尾成立
总台账统管其余九本整合管理统领成立（教材口径：整合跨全部过程组）
指挥部大权独揽、部门经理靠边站所有组织结构都如此失效：职能型/弱矩阵里权力其实在部门经理手里，结构决定权力
天气预警=只防坏天气风险管理只管威胁失效：风险也含机会（应对策略有「开拓/分享」）
启动挂帅章程立，规划图纸细如米；
执行大干人马齐，监控盯账不松气；
收尾验收交钥匙，整合统领军令起；
矩阵越强权越大，风险先识后分析。

项目运营

10小结

  • ① 项目=临时性+独特性；管理动作=五大过程组（启动/规划/执行/监控/收尾），管理内容=十大知识领域（整合统领其余九个）。
  • ② 组织结构从职能型→弱矩阵→平衡矩阵→强矩阵→项目型，项目经理权力从小到大，预算控制权跟着权力走。
  • ③ 风险管理流程顺序不可乱：识别→定性→定量→应对→监控；风险不只防坏事，也抓机会。
