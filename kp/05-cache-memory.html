05 · 存储层次与Cache

1一句话核心

小而快的缓存挡住大而慢的内存，局部性是金字塔成立的根基。

2先想后学：真实工程场景

🏗️ 场景游戏引擎团队把热数据数组从内存搬到「更靠近 CPU」的地方还不够，帧率仍卡顿。性能分析显示：数组每 4KB 就有一个元素被访问，而 L1 Cache 只有 32KB、4 路组相联——数据明明都在 Cache 容量以内，为什么命中率还是上不去？
💡 点开看思路与答案

因为 容量小不等于不冲突。直接映射/组相联下，主存块「按地址规则」进固定的行：两个常用块若映射到同一行，就会互相顶替（冲突缺失），命中率照样崩。这不是容量问题，是映射规则问题——对策是改组相联/全相联、或把数据布局错开（padding）。本页从存储金字塔讲到映射、替换、写策略，最后落到两个考计算题的口径公式。

3知识卡片

是什么

存储层次是一金字塔：寄存器 → Cache（L1/L2/L3）→ 内存 → SSD/磁盘，越往上越快、越小、越贵。CPU 旁的 Cache 是主存热点数据的副本（本域比喻：随手抽屉 vs 办公桌）。它成立的根基是局部性原理：刚用过的信息很快再用（时间局部性）；用过某地址，其邻居也将被用（空间局部性）。

解决什么问题

CPU 快、内存慢，速度差近百倍（一般认为的量级）；没有 Cache，01 页动画里「市政府干等办公桌」会占去绝大多数时间。Cache 让绝大多数访问在抽屉里就地完成，平均访问时间被拉到接近 Cache 的水平。

核心机制

命中率与平均访问时间（设命中率 h，Cache 访问 t_c，主存访问 t_m）：

口径公式例：h=0.9, t_c=5ns, t_m=100ns
同时访问（两级同时启动，谁先中用谁）T = h·t_c + (1-h)·t_m0.9×5+0.1×100 = 14.5ns
先 Cache 后主存（未命中才去，时间要相加）T = h·t_c + (1-h)·(t_c+t_m)0.9×5+0.1×105 = 15ns

两口径只差在「缺失时是否额外多花一次 t_c」，审题必须看清。

关键细节

机制做法代价/特点
直接映射主存块号 mod 行数 → 固定行硬件最省、不用比较全部；冲突缺失多
全相联可放任意行，全部标记并行比较命中率高；比较器贵，只宜小容量
组相联先按组号定组，组内任意放前两者的折中，主流选择（如 4/8 路）
替换算法LRU（最久未用先换出）、FIFO、随机LRU 依据时间局部性，最常考
写穿透 write-through写 Cache 同时写主存一致性好、写慢
写回 write-back只写 Cache 置脏位，换出时才写主存写快；存在与主存暂时不一致的窗口

现代 CPU 用多级 Cache：L1 小而快（几十 KB）、L2/L3 更大更慢，逐层兜底；缺一级就去下一级。

⚠️ 易错点①两种口径题年年有：「同时访问」用 h·t_c+(1-h)·t_m；「先访问 Cache 未命中再访问主存」必须相加，选错选项就差一次 t_c；②命中率低不一定是容量小，可能是映射冲突（本页开场案例）；③Cache 与缓冲（Buffer）不是一回事：Cache 为「快」存副本，Buffer 为「稳」吸收速度差。

专业英语小贴士

cache hit / miss（命中/缺失）；hit ratio（命中率）；locality of reference（访问局部性）；write-back / write-through（写回/写穿透）；L1/L2/L3 cache（多级缓存）。

4生活类比与口诀

你是办公室里办事的「市政府」：随手抽屉（Cache）里放这几天最常翻的文件，办公桌（内存）放本月卷宗，档案馆（磁盘）存历年档案。抽屉只放「大概率马上要用的」，这就是局部性；抽屉满了就挑「最久没人翻的」清出去，这就是 LRU；你在抽屉里改了数字先不还档案馆、等文件被换出时再抄回去，这就是写回法——档案馆在此期间看到的还是旧数。

类比项概念项成立/失效
常用的放抽屉热点副本、局部性成立
最久没人翻的先清出LRU 替换成立
抽屉改了数办公桌立刻知道写回法下主存同步更新失效：写回法要等换出才同步，期间主存是旧值
抽屉越大越好用Cache 容量决定一切失效：映射冲突也会压垮命中率，且容量受成本与功耗约束
抽屉办公桌两重天，局部性好抽屉甜；
命中快慢两口径，同时各取先后加；
映射冲突莫怪容量，直接相联定行忙；
写穿同步慢而稳，写回置脏快提防。

易混概念对比

写穿透（write-through）写回（write-back）
差异点写 Cache 同时写主存，始终一致只写 Cache 置脏位，换出时才写主存
易错点以为写穿透一定更快（写多时主存成瓶颈）忘记脏数据在掉电/异常时会丢，需要补救机制
一句话区分写穿透用「写慢」买「一致」，写回用「不一致窗口」买「写快」。

10小结

  • ① 存储金字塔靠局部性成立：时间局部性喂替换算法（LRU），空间局部性喂块调入。
  • ② 平均访问时间两口径：同时访问 h·t_c+(1-h)·t_m；先 Cache 后主存要相加 (1-h)·(t_c+t_m)，审题定生死。
  • ③ 直接映射省硬件但会冲突，组相联是主流折中；写穿透求一致、写回求快但留脏数据窗口。
