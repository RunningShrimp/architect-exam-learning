47 · 创建型模式

1一句话核心

创建型模式把 new 的权力收归工厂：单例全家独一份，建造者按订单组装。

2先想后学：真实工程场景

🏗️ 场景促销当晚，运营后台的数据出现诡异现象：部分用户看到的库存是旧的。排查发现——库存调度器是普通类，高并发下被两个线程各自 new 了一份，两份调度器各自维护一份内存库存，谁也不知道谁。同时，团队还要为 4 个支付渠道各写一套「App 证书 + H5 证书 + 回调验签器」的初始化代码，拷贝粘贴已开始失控。这两个问题，分别该用哪张「定型设计图」？
💡 点开看思路与答案

问题一是单例没守住：把构造器私有化、自己持有唯一实例、只发 getInstance() 一个入口，并用双检锁保证并发下也只创建一次（本页动画就是这条时序）。问题二是抽象工厂的地盘：每个渠道是一族产品（证书×2 + 验签器），要「成套创建、成套切换」，就把每族收进一个工厂，新增渠道 = 新增一个工厂子类——创建逻辑不再散落。

3知识卡片

是什么

创建型模式（5 个）管一件事：把「对象怎么造、造几份、谁说了算」从使用方手里收走，封装到专门的创建结构里。调用方只说「我要一个能算账的东西」，不必知道是哪个类、怎么 new、参数怎么填。

解决什么问题

直接 new 有三宗罪：①写死类名——换实现要满地改代码（违依赖倒置）；②重复创建重活——重量级对象每次都从头建；③全局状态失控——该唯一的东西被造出好几份。创建型把这三类麻烦各堵一堵。

核心机制：五张图各记「意图 + 城市比喻 + 适用场景」

模式意图城市比喻适用场景
单例 Singleton保证一个类仅有一个实例，并提供全局访问点全市唯一的总调度台全局唯一资源：配置中心、连接池、日志器、库存调度台
工厂方法 Factory Method定义创建对象的接口，让子类决定实例化哪个类预制件厂按型号供货：一个厂一条产品线一个产品等级结构（如多种数据库连接器），新增产品靠加子类
抽象工厂 Abstract Factory提供接口，创建一系列相关产品（一个产品族）家具城成套供货：欧式桌+欧式椅+欧式柜一起换多产品族成套创建与整体切换（换 UI 主题、换支付渠道全家桶）
建造者 Builder把复杂对象的构建过程与表示分离，同样的步骤可组装出不同表示装修按订单一步步来：毛坯→水电→精装，步骤固定、配置不同参数多、组装有顺序讲究、同一过程产出不同形态（文档导出器）
原型 Prototype用克隆已有实例来创建新对象复印盖章：不重新画图，复印一份再改批注创建成本大（查库/渲染）且新对象与已有对象状态相似

关键细节 1：单例的线程安全——双检锁（DCL）

并发下「先判空再创建」不是原子的：A、B 同时判空都为真，各造一份。解法是双重检查加锁：第一次判空（已存在就不必进锁，快）→ 加类锁 → 第二次判空（等锁期间可能已被别人创建）→ 创建并赋值。赋值用的引用要加 volatile：防止「分配内存→初始化→赋引用」被指令重排成「赋引用→初始化」，导致别的线程拿到半初始化实例。更省心的写法还有静态内部类Holder 和枚举（利用类加载机制天然线程安全）。

关键细节 2：工厂方法 vs 抽象工厂（必考对比表）

工厂方法抽象工厂
产品维度一个产品等级结构（一种产品多个型号）多个产品等级结构组成的产品族
工厂提供一个创建方法一组创建方法（每个产品一个）
扩展方式新增一个产品 → 新增一个工厂子类新增一族产品 → 新增一个工厂子类；新增产品种类要改所有工厂（不满足开闭）
一句话一个厂一条产品线一个厂一条成套生产线

关键细节 3：三张代表模式类图（空心三角=泛化/实现，空心菱形=聚合）

⚠️ 易错点①双检锁漏了第二次判空会重复创建、漏 volatile 会拿到半初始化对象——两个漏点分别对应「多个实例」和「字段是默认值」两种事故；②工厂方法 vs 抽象工厂判据是「一个产品等级 vs 一个产品族」，不是工厂类的数量；③「简单工厂」（一个静态方法 + switch）不属于 GoF 23，它把创建逻辑堆在一个类里，新增产品要改它——恰是工厂方法要解决的；④建造者 vs 工厂方法：工厂一步造好「是什么」，建造者分步组装且步骤/表示可分离；⑤原型要区分浅拷贝与深拷贝——浅拷贝共享引用字段，克隆体改状态会串门。
🔤 专业英语小贴士singleton（单例）· factory method（工厂方法）· builder（建造者）。英语题常用句式：The singleton pattern ensures that a class has only one instance and provides a global point of access to it.

向后：我为这些后续点埋下伏笔

  • 48 · 结构型模式：创建出来的对象开始「拼装」——单例的对象常被代理/装饰包一层（如给全局调度台加访问控制）；
  • 49 · 行为型模式：对象造好了开始「协作」——工厂常与策略/观察者搭配（按配置选策略、创建后注册进主题）；
  • 38/39 · 微服务与云原生：单例思想放大到服务级就是「全局唯一配置中心/注册中心」，而它的新麻烦（分布式单点）也在那里等着你。

易混概念对比

工厂方法抽象工厂
差异点一个产品等级结构：一种产品的多个型号（一厂一型）一个产品族：多个配套产品成套创建（一厂一套）
易错点以为「有多个工厂类就是抽象工厂」——判据是产品维度不是工厂数量以为抽象工厂处处更强——新增「产品种类」（不只是新族）要改所有工厂，反而破坏开闭
一句话区分换「型号」用工厂方法，换「整套风格」用抽象工厂；先问要换的是一个零件还是一屋家具。

10小结

  • ① 创建型 5 个管「生」：单例（唯一份+双检锁）、工厂方法（一厂一型）、抽象工厂（一厂一族）、建造者（分步组装、过程与表示分离）、原型（克隆创建、注意深拷贝）。
  • ② 单例三要素：私有构造、静态自持、getInstance()；并发正确性靠「两次判空 + 类锁 + volatile」，或静态内部类/枚举。
  • ③ 选型先问三句：要几份（单例）？换的是型号还是整套（工厂方法/抽象工厂）？是「造什么」还是「怎么一步步装」（工厂/建造者）？创建成本大就克隆（原型）。
