2先想后学：真实工程场景

🏗️ 场景某银行采购核心系统，招标文件写明：「中标方须交付可被工具自动分析的架构描述，能自动检查构件接口匹配与一致性」。架构师小王犯嘀咕：我们平时交付的都是框图和 Word 文档——图是人看的，工具怎么「读」？另有一个遗留的清算系统跑了 15 年，文档全丢、老人退休，新需求没人敢动。这两件事各需要一个什么「手艺」？
💡 点开看思路与答案

第一件事要 ADL（架构描述语言）：用形式化语法描述构件、连接件、配置，工具就能自动做一致性检查、类型检查甚至死锁检测——图纸从「给人看的画」升级为「给机器读的模型」。第二件事要 架构复原（重构）：从代码、运行日志与老员工记忆中反推出系统的真实架构，再文档化。两件事共同指向本页主题：架构必须被描述、被记录、可追溯，否则评估（44 页）与演化（45 页）都是空中楼阁。

3知识卡片

是什么：ADL 三要素

ADL（Architecture Description Language，架构描述语言）是用形式化语法描述软件架构的语言。与框图工具的区别：它有精确语义，能被工具分析（一致性、类型匹配、行为性质）。三要素正是 33 页架构三要素的「文字化」：

要素描述什么类比
构件（Component）计算或数据存储单元，带接口（端口 Port）规划图里的建筑
连接件（Connector）构件间的交互机制（管道、RPC、事件），带接口（角色 Role）道路与管线
配置（Configuration）构件与连接件如何连接组合的拓扑规则（Attachment/约束）管线接驳图与红线

考点句：在 ADL 中，连接件是一等公民（first-class entity）——它像构件一样有类型、接口与语义，可以被单独定义、分析与复用；而普通建模图里的「连线」只是线。这也是 ADL 区别于 UML 的关键之一。

典型 ADL 一览（对号入座题）

ADL特色（一句话）
ACME通用架构交换/互换描述语言：七类实体（构件、连接件、系统、端口、角色、表述、属性），定位是「架构的 PDF」——不同工具间交换架构描述
Wright侧重连接件行为形式化，可做死锁检测等性质分析

架构文档化原则

  • 涉众导向：文档为读者服务——不同干系人看不同视图（回扣 33 页 4+1），不追求「一张图包打天下」；
  • 版本化：架构文档是配置管理对象，纳入基线、随版本受控（联动 32 页）；
  • 可追溯：需求→架构决策→视图元素能对上账；决策要记「为什么」（架构决策记录 ADR 的思想）；
  • 充分且最小：写到足以指导与分析即可，过度文档没人读=失效；
  • 同步演化：架构改了文档必须跟着改，过期文档比没有更危险。

架构复原（重构）

架构复原（Architecture Reconstruction/Recovery）：对文档缺失的既有系统，从代码静态分析、运行时动态追踪、领域知识与人员访谈三条线半自动反推架构，再验证（与运行时行为比对）、文档化。它与「逆向工程」同源：逆向工程恢复设计与结构信息，架构复原专指恢复到架构抽象层级。

🔤 专业英语architecture description language（架构描述语言）· first-class connector（连接件一等公民）· traceability（可追溯性）· architecture reconstruction（架构复原）
⚠️ 易错点① ADL≠UML：UML 是通用建模语言、连接件不是一等公民；ADL 面向架构层级、支持形式化分析——考试爱把两者当「同类」混选；② 连接件不是「一根线」：管道、RPC、事件各有语义与类型，接错类型工具能查出来；③ 「架构文档=画图」错——文档包括视图+决策记录+质量说明，且要版本化受控；④ 架构复原≠代码重构（重命名提取函数那种）：复原是「恢复架构视图」，重构是「改善内部结构」。

4生活类比与口诀

ADL=建筑图纸的「CAD 格式」：手绘框图像美术画，好看但算不了受力；CAD 模型有精确尺寸语义，软件能自动检查「这根梁承重不够」——ADL 让架构图同样「可算」。连接件是一等公民=市政图里「道路」不只是线，而是有宽度、限速、通行规则的对象，可以单独设计审查。架构复原=老宅测绘：图纸丢了的老宅，测量队用卷尺（静态分析）、住客口述（访谈）、翻修记录（动态日志）三方对照，重新画出可信的图纸。

图纸给施工队看文档涉众导向成立
构件连接加配置，ADL 三宝要牢记；
连接件是一等公民，ACME 交换无异议；

易混概念对比

ADLUML
定位面向架构层级的描述语言，构件/连接件/配置有形式语义通用软件建模语言，覆盖需求到实现的多种图
连接件一等公民：有类型、接口（角色）与语义多用依赖/关联等关系表达，不是一等实体
易错点以为 ADL 只是把框图翻译成文字——核心价值是「可被工具分析」以为 UML 能完全替代 ADL——架构级形式化分析是 UML 的短板
一句话区分UML 是「全科室通用的画图笔」，ADL 是「专为总规做的可计算模型」。
