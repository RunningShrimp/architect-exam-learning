10 · 同步互斥与PV操作

1一句话核心

信号量是带计数的车位钥匙：P 占位、V 放行，负值是排队人数。

2先想后学：真实工程场景

🏗️ 场景某秒杀接口：库存 stock=100，扣减逻辑编译后就是两条机器指令——「把 stock 读进寄存器 → 寄存器减 1 写回」。峰值时两个进程几乎同时各扣 1 次，最终库存却只减了 1；长期运行甚至出现负库存（超卖）。问题：两条指令都正确执行了，为什么结果不对？
💡 点开看思路与答案

两条指令本身都对，但「读—改—写」这个序列不是原子的：进程 A 读到 100，还没写回，进程 B 也读到了 100，随后 A 写回 99、B 也写回 99——两次扣减只生效一次（丢失更新），这就是竞态条件。修法不是换指令，而是给「读—改—写」这段临界区上一把锁：一次只放一个进程进来。这把锁的标准实现，就是本页的主角——信号量与 PV 操作。

3知识卡片

是什么

多个并发进程共享的东西里，一次只允许一个进程使用的叫临界资源（如打印机、共享变量），进程中访问临界资源的那段代码叫临界区。互斥（Mutual Exclusion）= 竞争关系：一次只放一人进临界区；同步（Synchronization）= 合作关系：进程按一定次序推进，「你先做完我才能开始」。信号量（Semaphore）是一个整型变量 S 加两个原语（执行中不可打断）：P(S) 申请资源，V(S) 归还资源——由 Dijkstra 提出，P 来自荷兰语「减小」，V 表示「增加」。

解决什么问题

并发进程中「读—改—写」这类操作交叉执行时，结果不可再现（竞态）。用纯软件标志位实现互斥要么出错、要么「忙等待」空转浪费 CPU。信号量把「抢不到就睡、有人归还就叫」交给内核，实现无忙等待的互斥与同步。

核心机制：P 与 V 的精确定义

P(S):  S = S - 1;
       if (S < 0)  本进程阻塞，进入 S 的等待队列;
V(S):  S = S + 1;
       if (S <= 0) 从等待队列唤醒一个进程;

S > 0：还剩 S 个可用资源；S = 0：资源刚好用完，无人等待；S < 0：|S| = 正在排队等这个信号的进程数。初值的设定：互斥信号量初值 1；同步信号量初值 = 可用资源数 / 需要等待的事件数；「等某件事发生」的同步信号量初值 0。

核心机制：生产者—消费者（必背）

semaphore mutex = 1;   /* 互斥：保护缓冲区本身 */
semaphore empty = n;   /* 同步：空缓冲格数 */
semaphore full  = 0;   /* 同步：产品格数   */

生产者                          消费者
while (true) {                  while (true) {
  生产一个产品;                    P(full);   /* 先等货 */
  P(empty);   /* 先申请资源 */     P(mutex);  /* 再进临界区 */
  P(mutex);   /* 后申请互斥 */     从缓冲区取出产品;
  把产品放入缓冲区;                V(mutex);  /* 先退出临界区 */
  V(mutex);   /* 先放锁 */        V(empty);  /* 再还空格 */
  V(full);    /* 后发通知 */       消费产品;
}                               }

两个 P 的顺序不能颠倒：若生产者先 P(mutex) 再 P(empty)，缓冲区满时它会握着锁睡在 P(empty) 上，消费者连临界区都进不去，无法取货——死锁。

核心机制：读者—写者

规则：允许多个读者同时读；写者与任何人（读者、其他写者）互斥。核心技巧是读者计数器：第一个读者替全体读者锁门，最后一个读者开门。

int readcount = 0;          /* 当前读者数（共享变量） */
semaphore w = 1;            /* 写者锁，第一个读者也要用它 */
semaphore mutex = 1;        /* 保护 readcount 本身 */

读者:                           写者:
P(mutex);                       P(w);
  readcount++;                  执行写操作;
  if (readcount == 1) P(w);     V(w);
V(mutex);
执行读操作;
P(mutex);
  readcount--;
  if (readcount == 0) V(w);
V(mutex);

专业英语小贴士

Semaphore（信号量）、Critical Section（临界区）、Mutual Exclusion（互斥，简称 mutex）。英语题干里的「atomic operation」指原语操作——执行过程不可被中断。

⚠️ 易错点 ① P/V 必须成对出现；同一进程内「先申请资源、后申请互斥」，释放顺序 V 一般不敏感（惯例先放锁）。
② S 的负值绝对值 = 等待进程数，不是「负的资源」，更不是被取走的数量。
③ 互斥初值 1、同步初值看资源数——把互斥初值设成 0，第一个进程就被永久挡在门外。
④ 生产者-消费者有两个信号量时，P(empty) 在 P(mutex) 之前；颠倒顺序在缓冲满/空时必死锁。

4生活类比与口诀

🏛️ 市政厅的地下停车场：信号量 S = 剩余车位的钥匙数。P 就是伸手取钥匙：拿到一把就驶入（S 减 1）；柜子空了（S<0）只好在门口排队——排了几个人，S 就是几。V 就是还钥匙（S 加 1）：如果门口有人等，钥匙不回柜子、直接交到队首手里（唤醒一个进程）。钥匙总数固定 = 车位数，这就是信号量初值。

10小结

  • ① 信号量 = 整型计数 + P/V 两条原语：P 占位（减 1，负则睡），V 放行（加 1，有人等则直接唤醒交给它）。
  • ② 初值看语义：互斥 1、资源数 n、等事件 0；生产者-消费者用 mutex/empty/full 三件套，P 顺序「先资源后互斥」不能颠倒。
