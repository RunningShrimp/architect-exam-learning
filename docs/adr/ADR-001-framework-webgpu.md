# ADR-001：是否为学习站引入 React 类框架与 Three.js/WebGPU

状态：**已批准 GO（方案 B）并于 2026-09-02 开始实施** · 决策人：学员拍板「开始实施」
实施记录：期一 3D 知识图谱页（graph3d.html，入口在 2D 图谱页）✅；
期二 **已完成 5 个嵌入**（kp/05 缓存、kp/40 负载均衡、kp/37 请求分层、kp/19 缓存雪崩、kp/10 停车场 PV 信号量，
折叠块懒加载 iframe，关闭态零 vendor 实测=0）✅；
补充：Canvas2D 档补齐轻量代理模拟器（CitySim2D），兜底层嵌入不再静态——三处滑块联动实测生效；
实施中发现并落地：engine 迁移至 assets/scene-engine.js（正式资产）、vendor 提升至根 /vendor、
scene-embed.html 通用嵌入壳（静态 import map 规避动态注入竞态）、SW v8 对带 query 请求直连。
遗留观察：iframe 首启窗口 three 偶发不可用会按设计落 Canvas2D 档（31FPS 可用），待后续加探活重试；
three 层像素探针不可用（跨版本一致），视觉回归用截图+SSIM 与 Canvas2D 档探针替代。
评估人：前端架构评估师（AI） · 关联实验：poc/ 目录（可整体删除）

## 0. 硬边界（不可逾越）

零 CDN · 免构建常驻流程 · 离线 PWA · 移动端一等 · 既有性能预算（LCP/INP/app.js gz ≤50KB）· 非改造页面零回退（实测证明 ✅）。

## 1. 现状盘点与候选场景

现有交互全部 vanilla 达标（做题 1.1ms、图谱重绘 1.7ms、动画四控 30-60FPS、无长任务）。
候选场景与裁决：

| 场景 | 裁决 | 理由 |
|---|---|---|
| S1 3D 城市知识地图 | **候选（低优先）** | 隐喻天然契合，但现有 SVG 地图+图谱已覆盖导航功能；3D 是"体验增强"非"能力缺口" |
| S2 概念 3D 动画（缓存仓库/负载均衡车流） | **候选（中优先）** | 立体演示对"缓存层级/分流"这类空间概念确有教学增量；但现有 2D 动画已及格 |
| S3 粒子/Shader 氛围 | **砍掉** | 纯炫技，无学习收益，伤移动端预算 |
| S4 内容页组件化（React 类） | **砍掉** | 62 页是静态内容+统一引擎判题；无状态复用、无局部高频重渲染需求。React/Preact 在此是负资产（见 §3） |

## 3. 方案对比矩阵

| 维度 | A 保持 vanilla | B 隔离引入 three（POC 已验证） | C 全量框架重写 |
|---|---|---|---|
| 体积代价 | 0 | 仅 3D 页 +286~373KB gz（按需，入口页实测 0 加载） | React 44KB 常驻 + 全站迁移成本 |
| 性能预算 | 现状全 ✅ | 非 3D 页零回归 ✅（复测 index 200ms/0、kp/01 116ms/0） | 首屏 JS 翻倍，预算 ❌ |
| 开发复杂度 | 2D 手写已及格 | 3D 引擎 1 份 + 配置 JSON；已踩坑：探针回读、缓存键、档位链 | 整站重写，62 页回归 |
| 离线/移动 | ✅ | WebGPU 缺口由 WebGL2 兜底 ✅（Firefox Linux/Android 覆盖前必须保留） | 需重验 SSR/离线 |
| 维护成本 | 低 | **配置化后低**（见 §5） | 高（双技术栈） |
| **AI 可维护性（5B 实测）** | **再生成 4.5/5，一次成型** | 再生成 3/5（首轮缺 4 项规格未量化细节）；修改 5/5（三项需求全为 1 文件 1 轮）；视觉回归 3/5（three 层像素探针不可行→外部截图+SSIM=0.9873 可检测；Canvas2D 层 5/5）；升级演练 4/5（0.185↔0.182 引擎零改动互换，<5 分钟） | 未测（已被体积/收益否决） |
| 场景收益 | S1/S2 无增量 | S1/S2 可获得立体演示 | 与 S1~S4 无对应收益 |

被否方案论证：
- **C 全量重写 = NO-GO**：62 页静态内容的判题/进度/朗读已由 15.6KB 引擎覆盖；React 无状态复用可吃；体积与迁移风险双输；AI 维护反而引入框架版本/构建等新依赖维度。
- **Preact+htm 引入 = 暂不引入**：5.4KB 代价可接受，但 S4 砍掉后无使用场景；"为未来组件化预留"违反诚实原则。触发条件见 §6。
- **方案 A（完全 vanilla）**：成立——S1/S2 非缺口而是增强；若学员判断"当前 2D 动画教学效果已够"，A 是完全合法选择。

## 4. POC 实测记录（poc/ 目录，打开方式 http://localhost:8000/poc/index.html）

- POC-1 3D 城市地图：**默认档在本机 Chrome 实测 WebGPU**（非模拟）；10 分区 + 9 知识节点标签；拖拽/滚轮/**双指缩放** ✅；**点击楼块跳转 kp/33 落地实测 ✅**（4x CPU + 移动视口下）。
- POC-2 缓存仓库：滑块 95%→T=1.5s、5%→6.7s，14 顾客实体流，31 FPS ✅。
- 降级链逐级实测：WebGPU ✅ → WebGL2（自动/强制）✅ → Canvas2D ✅（像素探针全过）→ SVG ✅（6 可点击链接）。
- 4x CPU 降速 + 移动视口：WebGPU **30FPS**、WebGL 可玩（帧率下降可感知但无卡死）。
- 零回归：index LCP 200ms / CLS 0、kp/01 LCP 116ms / CLS 0、**vendorLoaded=false（入口/内容页零 vendor 加载）**、poc/ 不在 sw 预缓存 ✅。

## 5. AI 可维护性专项（阶段 5B 数据）

| 实验 | 过程数据 | 评分 |
|---|---|---|
| 再生成（three 3D，凭规格） | 1 轮出可运行场景；首轮缺失：雾效、标签投影、滚轮缩放、双指触控（规格未量化项），道路补齐为第 2 轮 | **3/5** |
| 再生成（Canvas2D 对照） | 1 轮一次成型，偏差仅装饰细节 | **4.5/5** |
| 修改 ×3 | ①便利店→无人售货柜：config-cache 1 行生效；②+3 知识节点：config-city 3 行生效（暴露"节点无标签"引擎缺口→顺手补齐，属一次性）；③镜头/节奏：2 行生效。**均为 1 文件 1 轮** | **5/5**（配置化后） |
| 视觉回归 | 人为 bug（档案馆 #d4b06a→#ff00ff）：外部截图+SSIM=**0.9873** 可检测 ✅；Canvas2D 层像素探针 got rgb(236,2,238) 精确捕获 ✅；**three 两后端（0.182/0.185）in-page readPixels 均黑帧 → three 层自动像素断言不可行**（跨版本一致结论） | **3/5** |
| 依赖升级演练 | 0.185→0.182：替换 3 个 vendor 文件，引擎零改动可运行（19 标签/交互全过）；全程 <5 分钟 | **4/5** |

**配置化结论：可行 ✅**。「场景 = JSON 配置 + 共享引擎（本 POC 的 engine.js 即雏形）」在三个修改实验中全部命中"AI 只改配置不改代码"；新场景类型需写一次 anim 插件（页面级注册，如 POC-2 的 cacheFlow）。这是长期维护成本的最大降本杠杆，**若 GO，所有 3D 场景强制走此模式**。

### 成本比结论

three 3D 场景相对 vanilla Canvas2D 的维护成本比 ≈ **1.4 : 1**（再生成 3 vs 4.5 分、探针受限、vendor 升级维度），配置化模式可把差距收窄到 ≈ **1.15 : 1**；但 three 换来的是 2D 无法表达的立体演示能力——**收益是否值得 15~40% 的维护溢价，取决于学员对 S1/S2 教学增量的判断，即本次拍板点**。

## 6. 路线图（GO 时）与重启条件（NO-GO 时）

**GO（方案 B）分期路线**（每期独立可回滚，撤销=删文件+还原 sw）：
1. 期一：3D 知识图谱页（poc/city3d 引擎 + graph 数据配置化），入口挂"实验"入口不设默认；
2. 期二：高价值概念 3D 动画 3~5 个（缓存/负载均衡/请求分层），嵌入对应 kp 页 as 可选折叠块；
3. 期三：复盘后再评估其余场景与 Preact。
随附《AI 维护手册》要点：场景一律 JSON+引擎；import map 锁精确版本；每次改动跑「探针（Canvas2D 档）+ 截图 SSIM」双检；vendor 升级=换文件+冒烟+SSIM 基线重建。

**NO-GO 重启触发条件**：Firefox Linux/Android WebGPU 发布且覆盖 >90%（兜底成本下降）；AI 3D 生成可靠性显著提升（再生成可稳定 1 轮全量覆盖，含雾效/相机等细节）；站点出现 2D 无法表达的交互需求（如学员投票要求立体演示）；或引擎复杂度自然增长到需要组件化时再评估 Preact。

## 7. 遗留

- three 层 in-page 像素探针在两后端/两版本均黑帧（已用外部截图+SSIM 与 Canvas2D 断言替代）；
- 真机（非模拟）触控与低端安卓实测未做（无设备），POC 已覆盖移动视口+4x CPU 模拟；
- Canvas2D 回退层的顾客流动画未实现（POC-2 顾客流仅 3D 档，2D 档静态——已在页面注明）。
