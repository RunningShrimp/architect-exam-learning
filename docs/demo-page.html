3知识卡片

是什么

缓存（Cache）是把热点数据的副本放在更靠近使用者的高速存储层。CPU 有 Cache，浏览器有缓存，应用服务器前有 Redis——它们是同一思想在不同层级的重复应用。

解决什么问题

存储越快越贵、越贵越小。如果没有缓存，每次读取都要走完全程（去最远的超市），慢且贵；缓存让「大多数请求」在半路就完成。

核心机制

平均访问时间 T = h×t快 + (1-h)×t慢，h 是命中率。h=0.95、便利店 10ms、超市 200ms 时：T = 0.95×10 + 0.05×200 = 19.5ms。命中率每提高一点，平均时间都在向「快的那一项」倾斜。

关键细节

概念城市比喻要点
命中 Hit便利店有货直接取走，全程最短
缺失 Miss便利店缺货去超市，再顺路补货（回填）
淘汰策略货架有限LRU=最久没人买的先下架
一致性超市改了价签便利店价签必须跟着改（失效/更新）
⚠️ 易错点公式里 h 与 (1-h) 的对象是同一时间口径的两级访问；考试常给「同时访问」与「先缓存后主存」两种口径，后者要把两级时间相加而不是取其一。

4生活类比与口诀

把缓存想象成你小区楼下的便利店：大多日用品楼下就能买（命中）；买不到才去 3 公里外的批发超市（缺失），回来时顺手多买几份存着（回填）。货架就那么大，最久没人买的先下架（LRU）。

类比项概念项成立/失效
便利店有货直接买缓存命中成立
缺货去超市顺路补货缺失后回填成立
货架最久未动先下架LRU 淘汰成立
超市改价便利店立刻知道缓存一致性失效：现实便利店不会自动同步，缓存必须靠失效机制
缓存便利店，命中走路近；
缺货去超市，回来货摆齐；
货架常清理，最旧先腾地；

10小结

  • ① 缓存=热点副本，T = h·t快 + (1-h)·t慢，命中率的威力是非线性的。
  • ② 缓存引出两件事：淘汰（LRU 等）与一致性（失效/更新）。
  • ③ 便利店的比喻记住「命中、回填、淘汰、同步」四个词就够。
